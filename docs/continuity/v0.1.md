# 1. CONTEXTO Y VISIÓN DEL PROYECTO

Estamos desarrollando **Plant OS**, un sistema inteligente de monitorización y cuidado autónomo de plantas domésticas.

La idea es construir un producto que pueda:

- Monitorizar las condiciones individuales de cada planta.
- Medir humedad del suelo y variables ambientales.
- Conocer las necesidades particulares de cada especie.
- Decidir cuándo necesita agua cada planta.
- Activar automáticamente el riego correspondiente.
- Registrar mediciones, decisiones y acciones.
- Evolucionar hacia el control de iluminación, temperatura, humedad ambiental y otras variables.

La visión a largo plazo es desarrollar un sistema operativo para plantas: una plataforma que conozca cada planta y gestione su cuidado independientemente de la maceta en la que esté.

**IMPORTANTE: Actualmente NO estamos trabajando en el business case ni en la estrategia comercial.**

Decidimos dejar temporalmente de lado:
- Investigación de mercado.
- Competidores.
- Pricing.
- Modelo de negocio.
- Potencial comercial.

El objetivo actual es exclusivamente construir un prototipo funcional de hardware y software y hacerlo funcionar en plantas reales.

# 4. PRIMERAS DOS PLANTAS

## Albahaca (Basil)

Características relevantes:
- Necesita humedad relativamente constante.
- Sensible a la falta de agua.
- Requiere buena iluminación.
- Sensible al frío.
- No debe permanecer encharcada.

## Romero (Rosemary)

Características relevantes:
- Prefiere que el sustrato se seque parcialmente entre riegos.
- Sensible al exceso de agua.
- Necesita buena iluminación.
- Requiere sustrato bien drenado.

IMPORTANTE: No definir porcentajes universales de humedad todavía. Los umbrales dependerán de la calibración del sensor, el tipo de sustrato, la maceta y las condiciones ambientales.

# 5. SISTEMA HIDRÁULICO

## Decisión de arquitectura

Se evaluaron tres alternativas:

1. Dos bombas independientes.
2. Una bomba central + dos electroválvulas.
3. Depósito elevado + riego por gravedad + válvulas.

La arquitectura recomendada para V0.1 es:

**Un depósito compartido + dos bombas peristálticas independientes de 12 V.**

Motivos:
- Independencia de cada maceta.
- Control preciso del volumen.
- No depende de la altura del depósito.
- No necesita válvulas adicionales.
- No requiere presión constante.
- Permite controlar cada planta desde el ESP32.

Se descartó temporalmente el riego por gravedad porque puede ser difícil obtener caudales estables con depósitos pequeños y goteros convencionales.

No obstante, no está descartado para futuras versiones.

## Circuito hidráulico

Recorrido:

Depósito de agua (3–5 litros)
→ Filtro de entrada
→ Distribución en dos circuitos independientes
→ Bomba peristáltica A
→ Tubo de salida A
→ Gotero A
→ Albahaca

Y paralelamente:

Depósito de agua
→ Bomba peristáltica B
→ Tubo de salida B
→ Gotero B
→ Romero

Cada bomba tiene su propia línea de aspiración y salida.

No es necesario instalar electroválvulas inicialmente.

## Componentes hidráulicos necesarios

| Componente | Cantidad | Especificación |
|---|---:|---|
| Depósito | 1 | 3–5 L, tapa |
| Filtro | 1 | 100–200 micras |
| Bomba peristáltica | 2 | 12 V DC |
| Tubos de aspiración | 2 | Compatibles con la bomba |
| Tubos de salida | 2 | Silicona, diámetro compatible |
| Gotero | 2 | Salida de baja restricción |
| Sensor de nivel | 1 | Flotador o equivalente |
| Válvula antirretorno | 2 | Opcional, según pruebas |
| Conectores | Según necesidad | Estancos |

No comprar goteros compensados convencionales sin verificar sus requisitos de presión. Las bombas peristálticas pequeñas pueden no proporcionar la presión necesaria.

Para V0.1 se recomienda comenzar con una salida calibrada o gotero de baja restricción.

# 8. CÁLCULO DE DOSIFICACIÓN

La fórmula que utilizaremos:

V = Q × t

Donde:
- V = volumen en ml.
- Q = caudal en ml/min.
- t = tiempo en minutos.

Con una bomba de 58 ml/min:

| Volumen | Tiempo teórico |
|---:|---:|
| 10 ml | 10,3 segundos |
| 20 ml | 20,7 segundos |
| 30 ml | 31 segundos |
| 50 ml | 51,7 segundos |
| 100 ml | 103,4 segundos |

Estos valores son únicamente teóricos.

Cada bomba deberá calibrarse individualmente:

1. Colocar recipiente graduado debajo de la salida.
2. Encender durante 30 segundos.
3. Medir el agua recibida.
4. Repetir cinco veces.
5. Calcular caudal promedio.
6. Guardar calibración individual.

No utilizar PWM inicialmente para regular caudal. Se prefiere trabajar a tensión nominal y dosificar mediante tiempo de funcionamiento.

# 9. CONEXIONES ESP32

Asignación propuesta:

| GPIO | Función |
|---|---|
| GPIO 25 | Control bomba albahaca |
| GPIO 26 | Control bomba romero |
| GPIO 34 | Sensor humedad albahaca |
| GPIO 35 | Sensor humedad romero |
| GPIO 21 | I2C SDA |
| GPIO 22 | I2C SCL |

GPIO 34 y 35 son entradas analógicas y no pueden utilizarse como salidas.

Los MOSFET se controlan mediante GPIO 25 y 26.

Esquema simplificado:

- Fuente 12 V positiva → bombas.
- Salida negativa de cada bomba → Drain de su MOSFET.
- Source → GND.
- Gate → GPIO correspondiente.
- GND fuente 12 V → GND ESP32.
- Diodo flyback por motor, con cátodo hacia positivo.
- Resistencia pull-down en cada Gate.

Las bombas deben arrancar apagadas, incluso después de reinicios.

# 10. FIRMWARE INICIAL

Código inicial para pruebas manuales:

const int PUMP_BASIL = 25;
const int PUMP_ROSEMARY = 26;

const int MAX_WATERING_MS = 10000;

void setup() {
  pinMode(PUMP_BASIL, OUTPUT);
  pinMode(PUMP_ROSEMARY, OUTPUT);

  digitalWrite(PUMP_BASIL, LOW);
  digitalWrite(PUMP_ROSEMARY, LOW);

  Serial.begin(115200);
}

void waterPlant(int pumpPin, int durationMs) {
  if (durationMs <= 0 ||
      durationMs > MAX_WATERING_MS) {
    Serial.println("Invalid watering duration");
    return;
  }

  digitalWrite(PUMP_BASIL, LOW);
  digitalWrite(PUMP_ROSEMARY, LOW);

  digitalWrite(pumpPin, HIGH);

  delay(durationMs);

  digitalWrite(pumpPin, LOW);

  Serial.println("Watering completed");
}
